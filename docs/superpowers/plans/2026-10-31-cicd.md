# qooob CI/CD implementation plan

> Execute inline. User approved staging/main, CI, automatic deployments, backups and rollback on 31 October 2026.

**Goal:** Feature branches -> staging -> main, with off-host checks/build and exact-artifact promotion.
**Architecture:** GitHub-hosted Linux Node22 checks. Staging receives a SHA256-manifested source/dependency archive over an SSH key restricted to a root-owned receiver. Production receives only a tree identity and promotes the previously health-checked staging artifact. Main merge commits are allowed only when their complete tree equals the accepted staging tree. Production preserves private configuration/data, compares a recorded baseline, backs up changed application files and restarts affected workers only.
**Stack:** GitHub Actions, Python3 standard library, Node22, systemd, PM2.

## Constraints
- Stage bot 9280625084; production bot 8344814605. No production secrets in staging/GitHub.
- No installs, builds or test suites on the 2GB shared host.
- Production never runs staging scripts; no copying runtime data or existing private paths.
- GitHub deployment credentials are restricted SSH keys; known-host pinning and server-side GitHub OIDC signature/ref/repository/tree verification required.
- Production promotion requires matching staged tree plus explicit acceptance recorded by an administrator after staging flow checks. Once accepted, main push deploys automatically; CI health alone is not functional acceptance.
- Do not force-push or modify unrelated services.
